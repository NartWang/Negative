> **本文件管辖范围**：仅 `src/app/` 内部。后端在 `src/engine/`，各有各的 CLAUDE.md。

## App 的核心使命

**一句话定位**：让每一天的牵挂，都变成可追的温暖故事

App 解决的问题不是"帮你写日记"，而是 — **把你忙碌、粗糙的日常，翻译成关心你的人能看懂、能感受到的画面和故事**。

### App 不是什么
- ❌ 又一个日记 App（市面已有 Day One/Journey 等）
- ❌ 又一个 emoji 心情追踪器（市面已有 Daylio）
- ❌ AI 教练 / 知识管家 / 个性化成长助手（远期愿景）

### App 是什么
- ✅ **情感翻译器**：日程+碎片输入 → 双 Agent 管线 → 画面+文字输出
- ✅ **家人的窗口**：让远在家乡的父母看到孩子真实的一天
- ✅ **沟通起点制造机**：给家人提供电话里"能聊起来的具体内容"

---

## 核心链路（开发时一切围绕这个）

```
记录（全天）→ 生成日记（晚上）→ 生成画面 → 确认 → 分享给关心的人
```

用户每天做两件事：
1. 记录日程和感受
2. 确认 AI 生成的日记和画面

其他全部交给 AI。

---

## 输入层：双轨道

### 日程轨道
- 添加日程条目（时间 + 标题）
- 完成后打勾
- 每条日程可附加感受（一句话描述当下情绪）
- 兼具习惯养成功能（打卡连续性追踪）

### 碎片轨道
- flomo 式快速输入（一句话 / 一段感想）
- 支持上传照片
- 可选心情标签
- 随时随地记录，不限时间不限格式

### 打卡系统
- 月视图日历，显示每天是否记录
- 连续记录天数统计（streak）
- 长时间未记录亮红灯提醒

---

## 生成层：双 Agent 管线

### 日记 Agent（GLM-5.1）
- 输入：当天全部日程（含完成状态和感受）+ 碎片记录 + 照片描述
- 输出：一篇温暖的日记文字，第二人称叙述
- 情感模式由用户选择

### 绘图 Agent（Qwen-Image-2512-Lightning，可更换）
- 输入：确认后的日记文字 + 用户选择的绘图风格
- 输出：对应风格的图片
- 绘图风格由用户选择

### 用户确认环节
- 预览日记文字，可编辑润色
- 预览生成的图片
- 可重新生成（换风格/换模式）
- 确认后保存到日记本

---

## 输出层：P0/P1/P2 分层

### P0 — 图片导出（必须丝滑）
- 保存生成的图片到本地
- 用户自行分享到微信/钉钉/朋友圈

### P1 — 分享链接（时间充裕再做）
- 生成 Web 页面链接
- 对方打开看到日记文字 + 图片
- 日记连续形成日记本，可翻看历史
- 支持周记自动汇总

### P2 — 双端互动（远期，不在 48h 范围）
- 邀请码配对建立"关心关系"
- 对方在分享页面可评论/点赞
- 家庭顾问简报

---

## 个性化设置

### 情感模式（控制日记文字基调）
- 真实传达 — 如实呈现情绪，用柔和方式表达
- 温暖滤镜 — 重心放在积极面，让对方安心
- 幽默轻松 — 把辛苦的事讲成段子
- 诗意文艺 — 把日常升华成散文/诗
- 自定义 — 用户一句话描述想要的风格

### 绘图风格（控制图片视觉风格）
- 四宫格手绘线条
- 连续叙事漫画
- 水彩图文日记
- 像素复古风
- 治愈系插画（吉卜力感）
- 自定义 — 用户描述想要的画面感

**设计原则**：预设模式降低门槛，自定义释放创造力。用户描述直接拼入 AI 提示词。

---

## 页面结构：底部导航栏 4 个 Tab

### Tab 1：今天（Today）— 今日全景
- 打卡状态卡片（连续天数 + 今日是否已记录）
- 今日日程列表（可直接打勾 + 快速加感受）
- 今日碎片流（最近几条速记预览）
- 悬浮「+」按钮（快速记录入口）
- 「生成今日日记」按钮（有内容后出现）

### Tab 2：记录（Record）— 输入中心
- 日程管理视图（添加/编辑/删除日程，每条可附感受）
- 碎片速记输入框（文字 + 照片上传）
- 打卡日历（月视图，颜色区分记录状态）

### Tab 3：日记本（Diary）— 输出画廊
- 日记时间线（按天排列，每天一张卡片缩略图）
- 点击 → 日记详情（文字 + 图片全屏展示）
- 导出图片按钮
- (P1) 分享链接按钮

### Tab 4：我的（Mine）— 设置与偏好
- 情感模式选择（预设 + 自定义）
- 默认绘图风格选择（预设 + 自定义）
- AI 生成提醒时间设置

## 技术栈

| 层 | 选型 | 理由 |
|---|------|------|
| 前端 | React + TypeScript | 类型安全 + 组件化 |
| 后端 | FastAPI（Python）+ SQLite | 零外部依赖，单文件数据库 |
| AI 日记 | GLM-5.1 | 中文友好 |
| AI 绘图 | Qwen-Image-2512-Lightning | 中文 prompt 友好，风格可控 |
| 部署 | WeaveFox Studio / AI Pages | 一键发布 |

**关键约束**：
- 数据存储走后端 API + SQLite（统一架构，避免后续迁移）
- AI 生成始终走后端 API（代理 AI 调用，避免前端暴露 API Key）
- 移动端优先（响应式，手机体验为主）

## 视觉风格统一约定

| 维度 | 选型 |
|------|------|
| 色系 | 莫兰迪 / 低饱和 / 暖色基调 |
| 字体 | 圆润中文字体（不要默认无衬线）|
| 图风 | 水彩 / 手账 / 治愈 / 大量留白 |
| 排版 | 像翻一本绘本，不是看一个 App |
| 语气 | 第二人称，温柔不油腻，像一个安静的朋友 |

视觉的失败定义：**让家人看到觉得"是机器做的"** → 直接砍掉。

---

## 禁止事项

- ❌ 偏离核心闭环去做其他功能
- ❌ P0 链路未跑通前做 P1/P2
- ❌ 让用户填超过 3 个字段才能产出内容
- ❌ 用默认 AI 生图风格（必须是手绘/水彩/治愈系）
- ❌ 漫画里出现冷冰冰的 AI 痕迹（机械感、模板感、英文水印）
- ❌ 前端直接调用 AI API（必须走后端代理）
- ❌ 引入外部数据库依赖（只用 SQLite）

---

## 设计自查

每加一个功能前问：
- 这个功能能让"记录 → 画面 → 分享"的链路更丝滑吗？
- 用户为了用这个功能要付出多少？（>30 秒就不行）
- 不做这个，核心闭环还成立吗？（成立就别做）
- 家人看到这个输出，会觉得温暖还是觉得是机器做的？
